# ADR-001: Вибір фрейморку для розробки бекенд частини

**Статус:** Прийнято

**Дата:** 2026-05-08

**Автор:** Maksym Paprotskyi

**Контекст:**

Потрібно обрати фреймворк для розробки бекенд частини

**Розглянуті варіанти**

**Express**

- Плюси: Велика екосистема, величезна кількість документації та плагінів, велике комюніті

- Мінуси: Повільніший за сучасні аналоги, відсутність вбудованої валідації (потребує сторонніх бібліотек), застаріла архітектура.

**Fastify**

- Плюси: Висока продуктивність, вбудована підтримка JSON-схем для валідації, архітектура плагінів для чистого коду.

- Мінуси: Менша кількість готових плагінів порівняно з Express.

**NestJS**

- Плюси: Чітка структура «з коробки», орієнтація на великі Enterprise-проєкти.
- Мінуси: Високий поріг входження, велика кількість абстракцій та «boilerplate» коду для невеликих сервісів.

**Прийняте рішення**

Обрано Fastify.

**Наслідки**

- Позитивні: Значне зменшення накладних витрат на обробку HTTP-запитів. Автоматична генерація типізації для відповідей/запитів на основі JSON-схем.

- Негативні: Розробникам доведеться вивчити специфічну модель інкапсуляції плагінів Fastify.

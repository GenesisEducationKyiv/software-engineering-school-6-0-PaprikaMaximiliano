# ADR-003 Вибір інструменту для роботи з базою даних (ORM)

**Статус:** Прийнято

**Дата:** 2026-05-08

**Автор:** Maksym Paprotskyi

**Контекст:**

Необхідно забезпечити надійну та типізовану взаємодію між сервісами та реляційною базою даних. Інструмент повинен підтримувати автоматичну генерацію типів для TypeScript та спрощувати процес управління міграціями.

**Розглянуті варіанти**

**TypeORM**

- Плюси: Широкі можливості для об'єктно-орієнтованого підходу.

- Мінуси: Складна конфігурація, іноді неочевидна поведінка при роботі зі складними зв'язками.

**Prisma**

- Плюси: Автоматична генерація клієнта з повною підтримкою TypeScript, декларативний опис схеми (schema.prisma), зручні та безпечні міграції

- Мінуси: Додатковий оверхед через Rust-ядро, складність виконання дуже специфічних сирих SQL-запитів.

**Drizzle ORM**

- Плюси: Максимально близький до сирого SQL, легкий.
- Мінуси: Потребує більше ручного опису типів порівняно з Prisma.

**Прийняте рішення**
Обрано Prisma.

**Наслідки**

- Позитивні: Максимальна безпека типів (Type Safety) на рівні коду. Швидкий онбординг нових розробників завдяки автодоповненню в IDE та зрозумілій схемі (schema.prisma).

- Негативні: У разі виконання дуже специфічних або складних аналітичних запитів продуктивність Prisma може падати, що вимагатиме використання $queryRaw. Для поточного проекту не є суттєвим мінусом.
